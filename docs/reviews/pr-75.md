## Findings

### P2-1: A valid heal can overflow before its health cap

Status: fixed in `15945f2`.

Open at: `26d20cc`.

File: `TheThingBelow.Core/Battles/BattleMath.cs:85-86`.

Trigger: Load valid content with a heal base, magic, and power of 100000, an aptitude bonus of 100000, and a hit factor of 100000. Each value meets the current content limits in `BattleFixture.ReadStat` and `BattleRules.CheckRanges`.

Expected: Apply the formula and cap the heal at the target's missing health (D-1057, D-1058, D-1059). A value within the health integer range must not crash the run (T-2).

Actual: `share` is 11000000000. The checked product `share * 110000 * 100000` exceeds `long.MaxValue` before division. The mathematically correct uncapped result is 121000000, which fits `int`.

Consequence: A valid ability can throw an uncontextualized `OverflowException` during a battle or menu heal, and stop the simulation before it can cap the result.

Correction: Reorder or bound the fixed-point calculation so it can compute the capped result without an overflowing intermediate. Preserve the single-rounding rule and add a maximum-valid-input regression test.

Regression check: Add a test with the stated limits. It must complete the heal and cap it at missing health without an `OverflowException`; run `make verify`.
