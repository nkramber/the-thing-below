## Findings

### P2-1: `frame-png` can overwrite its source drawing

Status: open.

Open at: `0cbf3ca8ca9fef24187344199707fc723ee8b2e6`.

File: `TheThingBelow.Tools/Import/FramePngCommand.cs:72-76`.

Trigger: Give `--drawing` and `--out` the same existing path.

Expected: The command writes a frame PNG without destroying the source drawing (D-1313, T-2).

Actual: `FrameTarget.Read` reads the drawing, then `PngWriter.WriteFile` truncates that same path and writes PNG bytes. A local reproduction returned exit code 0 and changed a copied drawing JSON file into a 32 by 32 PNG.

Consequence: One valid command invocation destroys the drawing file and its frames.

Correction: Reject an output path that identifies the drawing path before the write, and report both paths.

Regression check: Add a `FramePngCommandTests` case with identical input and output paths. It must return a fault and preserve every source byte.
