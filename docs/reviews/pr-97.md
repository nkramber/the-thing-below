## Findings

### P2-1: `frame-png` can overwrite its source drawing through a file alias

Status: fixed in `3aec94f52e18959026102bd784f35d8eb39d5d8b`.

Open at: `0cbf3ca8ca9fef24187344199707fc723ee8b2e6`, `7ca7b25106e18b8ed8234b0c66824c9e2e21d411`.

File: `TheThingBelow.Tools/Import/FramePngCommand.cs:73-90`.

Trigger: Pass the drawing path as `--drawing` and a symlink to that file as `--out`.

Expected: The command must not destroy the source drawing when it writes a frame PNG (D-1313, T-2).

Actual: `Path.GetFullPath` keeps the symlink path distinct from the target path. `PngWriter.WriteFile` follows the symlink and truncates the drawing. A local reproduction returned 0, and `file` identified the copied drawing as a PNG.

Consequence: A supported path alias lets a valid invocation replace the drawing and all its frames with PNG bytes.

Correction: `3aec94f5` opens output with `FileMode.CreateNew`, which rejects existing files and links. The same-path, symlink, and pre-existing-file tests confirm that the drawing and existing output bytes stay unchanged.

Regression check: `AnOutputLinkToTheDrawingFileFailsAndKeepsTheDrawing`, `AnExistingOutputFileFailsAndKeepsItsBytes`, and `AnOutputPathOfTheDrawingFileFailsAndKeepsTheDrawing` passed on `95048ef`. `CreateNew` also rejects a hard-link alias because the output name exists.
