## Findings

### P2-1: Snapshot restore accepts an undeclared story actor

Status: fixed in `498137c3dd482dc02a6868e3767635355a8acc07`.

Open at: `f8868ae511f51e6609d0d9fdc024164905386c22`.

File: `TheThingBelow.Core/Story/StoryState.cs:392-399`.

Trigger: Read a format 9 snapshot whose active story scene lists a shown actor such as `character.unknown`, then resume it with content that has no such character record.

Expected: Resume must reject a stored actor id that this build does not declare. The snapshot must describe a state of the loaded content (D-166, T-2).

Actual: The reader checks only that the id has kind `character`. `StoryState.Resume` checks duplicates, terrain, and tile collisions, then stores the id without checking the character records.

Consequence: A malformed save or run record restores a story actor that has no character data. The Core state accepts invalid content and any consumer that draws that actor cannot resolve its record.

Correction: `StoryContent` now keeps the cast ids of the build. `StoryState.ResumeScene` checks each restored actor against that cast before adding it to the story state (D-1006).

Regression check: `StorySnapshotTests.AStoryStateThatNoRunMakesFailsTheLoad` now includes an undeclared actor id. It passed with the valid actor round-trip case and all other snapshot cases, 27/27.
