## Findings

### P1-1: The export smoke command discards a failed process status

Status: open.

File: `.github/workflows/export.yml:276`

Trigger: The exported game prints `smoke: the session ends with no error.` and then exits with a nonzero status.

Expected: The export smoke step must fail when the exported process fails, and it must also require the success line. T-2 requires visible failure. The existing CI smoke step preserves the process status with `set -euo pipefail` and `tee`, and the PR roadmap requires each export to end the smoke session with no log error.

Actual: `"$game" --headless --quit-after 600 -- --smoke > export-smoke.log 2>&1 || true` converts every process failure into success. The later checks only search for a success line and error prefixes. A process can therefore return failure after writing the success line, and the job continues to package and upload that build.

Consequence: The export job can publish an artifact from a failed exported game and report a green leg. The required export deliverable is then not proven to run.

Correction: Preserve the process status. Use a `pipefail` pipeline or capture the status and fail after the log checks. Keep the success-line check because a zero status alone does not establish a loaded managed assembly.

Regression check: Add a workflow-contract test or an equivalent shell probe that rejects the `|| true` command and proves that a nonzero exported process fails the step. Run `make verify` and the export workflow checks again.
