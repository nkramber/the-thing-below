## Findings

### P1-1: The export smoke command discards a failed process status

Status: fixed in `82d1afd`.

File: `.github/workflows/export.yml:279`

Trigger: The exported game prints `smoke: the session ends with no error.` and then exits with a nonzero status.

Expected: The export smoke step must fail when the exported process fails, and it must also require the success line. T-2 requires visible failure. The existing CI smoke step preserves the process status with `set -euo pipefail` and `tee`, and the PR roadmap requires each export to end the smoke session with no log error.

Actual at the reviewed head: the command stores its exit code in `status`, runs the log checks, and fails when `status` is not zero. The same contract now applies to the `Makefile` smoke target. A regression test covers all three smoke callers.

Consequence: The export job can publish an artifact from a failed exported game and report a green leg. The required export deliverable is then not proven to run.

Correction: The correction captures the process status and fails after the log checks. It keeps the success-line check because a zero status alone does not establish a loaded managed assembly.

Regression check: `TheSmokeStepKeepsTheExitCodeOfTheExportedGame`, `NoCommandThatStartsTheSmokeSessionDropsItsExitCode`, and `TheMakefileSmokeTargetFailsOnANonzeroExitCode` pass in `make verify`. The author probe also reports that the old text exits 0 for a stub exit code of 3, while the new text exits 1.
