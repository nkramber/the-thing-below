## Findings

### P1-1: The verdict check accepts a negated approval

Status: fixed in `3a75767`.

File: `TheThingBelow.Tools/ReviewGate/ReviewRecordRules.cs:84-90`.

Trigger: Put `**Not Ready for owner merge.**` in the `## Verdict` section.

Expected: RG 4 accepts only the exact current verdict `Ready for owner merge` (D-15, D-17).

Actual: At `40ea275`, `CheckVerdict` searched for the approved phrase as a substring. It found one verdict name and passed, even though the text negated approval.

Consequence: A record that explicitly refuses merge can satisfy the review gate and allow a merge without an approval.

Correction: `CheckVerdict` reads the bold verdict name from the verdict section and checks it against the three allowed names.

Regression check: `ANegatedApprovedVerdictFails` passes on `3a75767` and faults on the old substring rule. `AVerdictSectionWithNoBoldVerdictLineFails` and `AVerdictLineOfBlockedFailsWhenTheProseNamesTheApprovedVerdict` also pass.

### P1-2: The head check accepts a field outside Identity

Status: fixed in `3a75767`.

File: `TheThingBelow.Tools/ReviewGate/ReviewRecordRules.cs:146-160`.

Trigger: Give `## Identity` a stale or absent head field, then add a matching `- Head:` line under another section.

Expected: RG 5 reads the head field from the Identity list alone (D-17, D-610).

Actual: At `40ea275`, `CheckHead` scanned every line of the record and accepted the first matching field, wherever it appeared.

Consequence: A stale or malformed review identity can pass RG 5 when unrelated text names the effective hash.

Correction: `CheckHead` reads the `## Identity` section alone and faults when that section or its head field is absent.

Regression check: `AHeadFieldOutsideTheIdentityListFails` and `ARecordWithNoIdentitySectionFails` pass on `3a75767`.

### P1-3: The verdict check ignores a later conflicting verdict

Status: open.

File: `TheThingBelow.Tools/ReviewGate/ReviewRecordRules.cs:90-98`.

Trigger: Put `**Ready for owner merge.**` and then `**Changes required.**` on separate lines in `## Verdict`.

Expected: RG 4 accepts one current verdict in the `## Verdict` section. A conflicting second verdict makes the record invalid (D-15, D-17).

Actual: `CheckVerdict` stops after the first bold verdict line. It returns pass for the first approved line and ignores the conflicting line.

Consequence: A review record that also states `Changes required` can satisfy the merge gate.

Correction: Require exactly one verdict line in the section, and require that line to contain only the approved verdict.

Regression check: Add tests for an approved line followed by a conflicting verdict line and for trailing conflicting text on the approved line. RG 4 must fault.

### P2-1: The deferral check misses spelled-out pull requests

Status: fixed in `3a75767`.

File: `TheThingBelow.Tools/ReviewGate/DocumentRules.cs:52-70,210-219`.

Trigger: A Documents line says a required record will be added by “a separate pull request.”

Expected: RG 8 faults when a Documents line defers a document or record of this PR to a later PR (D-577, D-578, D-579).

Actual: At `40ea275`, the phrase list contained “a separate pr” but not “a separate pull request,” so the line passed RG 8.

Consequence: A required document or record can be left for later while the machine check reports no deferral.

Correction: `DeferralPhrase` normalizes `pull request` to `pr` before it checks the phrase list.

Regression check: The two new `EachDeferralOfADocumentOfThisPullRequestFails` cases pass on `3a75767` for “a separate pull request” and “a later pull request.”
