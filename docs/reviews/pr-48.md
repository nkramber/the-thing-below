## Findings

### P1-1: Enemy records omit the required body size and map consistency check

Status: open.

File: `TheThingBelow.Core/Battles/EnemyRecord.cs:23-32,75-122`, `TheThingBelow.Core/Content/ContentSet.cs:209-233`.

Trigger: Load a supported content set whose map patrol names an enemy record but declares a different `size` from the enemy definition.

Expected: The enemy record declares the body size, and content loading rejects a map whose size disagrees with that record (D-754, D-206, D-209, D-236, T-2).

Actual: `EnemyRecord` stores only id, stats, and ability ids. `Patrol` still parses and stores the map `Size`, but `ContentSet.Load` performs no map-to-enemy size comparison. The mismatched content loads without an error.

Consequence: The same enemy can have different body dimensions in the battle record and map record. Map blocking and body-fit validation can then use a size that does not match the enemy definition.

Correction: Add the size field to each enemy record and validate every map patrol size against the referenced enemy record during content loading. Preserve file and id context in the mismatch error.

Regression check: Add a content-load test that changes one patrol size without changing its enemy id and asserts `ContentException` names the map, the enemy id, and both sizes. The test must fail at `fd97eb2` and pass after the correction.
