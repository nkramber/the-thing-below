## Findings

### P2-1: The PR comment export can succeed with missing comments

Status: fixed in `d2479ce`.

File: `docs/runbooks/session-context.md:95-102`.

Trigger: Any earlier `gh pr view` or `gh api` call in the grouped command fails, and a later call succeeds.

Expected: The command must fail when any source of PR comments or review data fails, so the reviewer cannot mistake a partial file for the complete evidence required by D-589 and T-2.

Actual: The command uses a brace group without `set -e` or `&&`. The exit status comes from the final call. A shell reproduction with a failing command followed by a successful command returned status 0 and wrote a partial file.

Consequence: A reviewer can miss a Gitar claim, author reply, or review comment while believing the required comment export completed.

Correction: Make every retrieval failure stop the command before it leaves a usable comments file. For example, use `set -e` and write to a temporary file that is renamed only after all calls succeed.

Regression check: `/tmp/pr16_export_regression.sh` ran on the prior and corrected runbook text in bash and zsh. The prior text returned 0 and left `comments.md` in both shells. The corrected text returned 1 and left no `comments.md` in both shells. This establishes the fix for the original trigger.
