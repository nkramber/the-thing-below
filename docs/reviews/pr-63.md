## Findings

### P2-1: The Gitar check ignores review threads after the first page

Status: fixed in `a7902e7`.

Open at: `ca9dd85`.

File: `TheThingBelow.Tools/CodexReview/CodexReviewCommand.cs:235-242`.

Trigger: A PR has more than 100 review threads, and an unresolved Gitar thread appears after the first 100.

Expected: The command refuses to start until every Gitar review thread is resolved (D-14, D-67).

Actual: The GraphQL query requests `reviewThreads(first: 100)` and does not read `pageInfo` or request another page. `GitarPass.Check` therefore sees no later thread and can accept an incomplete pass.

Consequence: The required Gitar review can remain open while the Codex review starts.

Correction: Read every page of review threads before checking the Gitar pass.

Regression check: Add a test with more than 100 threads and an unresolved Gitar thread on a later page. The start check must refuse the run.

### P2-2: Duplicate finding IDs do not share their three-strike count

Status: fixed in `a7902e7`.

Open at: `ca9dd85`.

File: `TheThingBelow.Tools/CodexReview/FindingRounds.cs:64-89, 126-138`.

Trigger: Two open finding sections have the same ID and share the current head, but their distinct `Open at:` heads total three. Each section lists fewer than three heads.

Expected: The same stable finding ID counts once per open review round, and an open finding that reaches three rounds stops the loop (D-929).

Actual: `Read` returns both sections as separate findings, and `Strikes` checks their counts separately. It does not reject or combine duplicate IDs.

Consequence: A malformed or duplicated record can avoid the owner stop that D-929 requires.

Correction: Reject duplicate finding IDs as a malformed record, or combine their round history by ID before counting.

Regression check: Add a record with duplicate IDs whose combined open rounds reach three. The command must fault or return the three-strike outcome.
