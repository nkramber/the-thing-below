## Findings

### P2-1: Softlock sampling can skip a softlocked state

Status: open.

Open at: `66dcf4db073d96abdf4e7bc1443ec8241b87e219`.

File: `TheThingBelow.Tools/Bots/BotRun.cs:134-136`.

Trigger: The runner reaches a state with no accepted intent that changes the state except the tick when `played` is not divisible by 60, and a later tick leaves that state.

Expected: End the run as softlock at every state that meets D-1179. Sampling every 60 ticks can miss such a state.

Actual: `SoftlockCheck.Holds` runs only when `played % SoftlockCheckTicks == 0`. At every other state, the policy and the tick proceed without a softlock check. A transient softlock can therefore pass without a failure record.

Consequence: The bot job can report success after it misses the exact softlock that D-1179 defines as a run end. The existing planted-softlock test starts at played tick zero and does not cover this case.

Correction: Check each state before the policy acts, or establish and test a rule that proves every softlock persists until the next sample. Measure the correction against the five-minute budget of D-1180.

Regression check: Add a test with a softlock at a non-sample tick that clears on a later tick. The run must end as softlock at that tick and write a replayable failure record. Re-run the bot timing measure.
