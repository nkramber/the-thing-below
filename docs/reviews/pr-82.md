## Findings

### P2-1: The selected conflicting binding loses its warning color

Status: open.

Open at: `0e71601a8ef762a9a5e0032e8346c682f0e06c18`.

File: `TheThingBelow.Game/scripts/Ui/SettingsScreen.cs:443-449`.

Trigger: A remap conflict includes the binding cell whose row is currently selected.

Expected: Every cell whose binding sits in a conflict uses the warning color (D-1119, F-146).

Actual: `ShowSlot` first paints the selected cell with `chosenColor`, then skips the warning override when `chosen` is true. The `settings-conflict-1x` artifact at this head shows the selected Back cell in yellow while the conflicting Confirm cell is red.

Consequence: The selected conflicting binding does not carry the warning color, so the grid does not mark every conflict as D-1119 requires. The baseline accepts this mismatch, and the new tests check `InConflict` but do not check the rendered color of a selected conflict.

Correction: Apply the warning color to every conflicting cell while retaining a separate visible cursor indicator for the selected row.

Regression check: Add a rendered-screen case with two conflicting bindings and one selected. Confirm that both conflict cells use the warning color and that the cursor remains identifiable. Run `make verify` and inspect the resulting screen-test artifact.
