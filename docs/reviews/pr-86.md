## Findings

### P2-1: A repeated line can retain the previous speaker

Status: fixed in `6b1b7d56e2754e8a7e4d9e8ebf1ad452700287e2`.

Open at: `cd1d45298ec5f2952a4864e74e10cd9c76658704`.

File: `TheThingBelow.Game/scripts/Ui/DialogueBox.cs:107-112`.

Trigger: Two consecutive `SayStep` values use the same line id and different speakers.

Expected: The dialogue box updates the portrait and name plate for the current speaker (D-223, D-997).

Actual: At `cd1d452`, `Show` called `ShowSpeaker` only when the line id changed. The second line kept the first speaker's portrait and name.

Consequence: The screen attributes dialogue to the wrong character under valid story content.

Correction: `DialogueChange` tells `DialogueBox.Show` to refresh the speaker when the speaker changes, even when the line id stays the same.

Regression check: `ScenePlayTests.ASecondSpeakerOfTheSameLineDrawsItsPortraitAndItsNameAgain` passes. It gives one line id to two consecutive say steps with different speakers, then asserts the second step redraws both the line and speaker.
