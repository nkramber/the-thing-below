## Findings

### P2-1: A repeated line can retain the previous speaker

Status: open.

Open at: `cd1d45298ec5f2952a4864e74e10cd9c76658704`.

File: `TheThingBelow.Game/scripts/Ui/DialogueBox.cs:107-112`.

Trigger: Two consecutive `SayStep` values use the same line id and different speakers.

Expected: The dialogue box updates the portrait and name plate for the current speaker (D-223, D-997).

Actual: `Show` calls `ShowSpeaker` only when the line id changes. The second line keeps the first speaker's portrait and name.

Consequence: The screen attributes dialogue to the wrong character under valid story content.

Correction: Refresh the speaker when the speaker changes, even when the line id stays the same.

Regression check: Add a dialogue box test with one line id and two speakers. The second step must show the second speaker's portrait and name, and the test must fail on this head.
