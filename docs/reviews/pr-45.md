## Findings

### P2-1: Large area coordinates can bypass patrol layout validation

Status: fixed in `801d6aa`.

File: `TheThingBelow.Core/Maps/PatrolLayout.cs:82-89`

Trigger: Load a map enemy with a positive area coordinate and width or height whose `int` sum overflows, such as `x: 2147483640` and `width: 100`.

Expected: Reject the map with a content error. Every area must lie inside the map, and the enemy body must fit at every valid anchor tile (D-209, D-741, T-2).

Actual: `CheckArea` evaluates `area.X + area.Width` and `area.Y + area.Height` in unchecked arithmetic. The overflowed value can make the boundary condition false. The later loops use the same unchecked sums and can execute zero iterations, so the invalid area can pass layout validation. `MapPatrols.Enter` then places the enemy at the invalid anchor without a `CanPlace` check.

Consequence: Malformed map content can create an enemy body outside the map. This breaks the content-load contract and can produce invalid simulation or presentation state from a supported external input.

Correction: Validate the area bounds with checked arithmetic, or compare width and height against the remaining map dimensions without forming an overflowing sum. Keep the body-fit checks active for every valid anchor.

Regression check: Add a content-load test with overflowing positive area bounds and assert a `ContentException` that names the enemy and area. Run `make verify`.
