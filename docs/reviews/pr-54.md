## Findings

### P1-1: The synchronize event has no previous head input

Status: open.

File: `.github/workflows/ci.yml:57-63,85-91`.

Trigger: GitHub runs this workflow for a `pull_request` `synchronize` event after a new commit reaches the PR branch.

Expected: The workflow must obtain the previous PR head and check runs so a docs-only push after a green head skips the jobs named by D-858.

Actual: The workflow assigns `BEFORE_REF` from `${{ github.event.before }}`. GitHub documents `before` as a field of the `push` payload. The documented `pull_request` payload does not provide the push-style `before` field. Therefore `BEFORE_REF` is empty for the event that this code handles, the condition at lines 88-91 exits without writing push facts, and the command receives no previous head. It returns `documents-alone=false`, so every docs-only synchronize push runs every build job.

Consequence: The main behavior of PR-93 does not operate on its supported push path. The workflow is safe in that it runs extra jobs, but it does not satisfy D-856, D-858, or exit test 2. The local command tests cannot detect this because they inject `pushPaths` and `previousChecks` directly.

Correction: Obtain the previous PR head from an event field that GitHub supplies for `pull_request` `synchronize`, or use a supported event/API design that can identify it. Add a workflow-level regression probe with the actual event shape and verify that the changed-paths job writes the previous-head facts.

Regression check: Run the CI workflow on two consecutive docs-only synchronize pushes after a green code head. The second run must report `documents-alone=true` and skip every listed build check. Add a test or fixture for the exact `pull_request` synchronize payload.
