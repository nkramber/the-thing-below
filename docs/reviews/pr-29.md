## Findings

### P2-1: Snapshot validation accepts an even random-stream increment

Status: fixed in `db432de`.

File: `TheThingBelow.Core/Runs/RunSnapshot.cs:69-76`.

Trigger: Read a record whose snapshot gives one stream an even `increment`, such as `0x0000000000000000`, then replay it.

Expected: Reject the invalid stream position with the snapshot line and field context (T-2, G-18, D-259).

Actual: On the original head, `RunSnapshot.Check` verified stream order but not increment parity. `RunRecordText.Read` accepted the record. `RunState.Resume` then called `Pcg32.FromSnapshot`, which threw a bare `ArgumentException` without the record line.

Consequence: A malformed record bypasses the record error contract, so its caller cannot report which line failed.

Correction: `db432de` validates that each increment is odd while the snapshot is checked, and calls `Check` inside `ReadSnapshot` so the reader preserves line 2 context.

Regression check: `AStreamIncrementThatIsEvenIsAnErrorOfTheSnapshotLine`, `AnEvenStreamIncrementNeverReachesAReplay`, and `ASnapshotWithTooFewStreamsIsAnErrorOfTheSnapshotLine` pass on `db432de`. The three tests failed on `ee1e6ea` for the original acceptance, bare exception, and whole-record context defects.
