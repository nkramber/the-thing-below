## Findings

### P1-1: The Menu action cannot close the menu

Status: open.

File: `TheThingBelow.Game/scripts/Boot.cs:222`.

Trigger: Press the Menu key or button after the menu is open.

Expected: The input contract sends `IntentIds.CloseMenu` when the menu is open, as `InputActions.IntentOf` and D-162, D-650 require.

Actual: `ReadInput` always calls `InputActions.IntentOf(action, false)`. The caller therefore sends `OpenMenu` for every Menu press. The `true` branch is unreachable from Game.

Consequence: A later menu cannot close through the input path, so the player cannot return from the menu with its assigned action.

Correction: Track the current menu-open state in the caller and pass that state to `IntentOf` for the Menu action. Update the state after the intent is made.

Regression check: Add a caller-level test or an equivalent input-path test that sends Menu twice and observes `OpenMenu` then `CloseMenu`.

### P1-2: PR-41 does not create the required screen-test job

Status: open.

File: `.github/workflows/ci.yml`.

Trigger: Inspect the workflow and run the PR checks after this PR merges.

Expected: PR-41 creates a Linux screen-test job under Xvfb with the pinned Mesa setup, captures the frame and both fit modes, and compares decoded pixels, as F-23, F-26, D-172, and the phase-2 roadmap require.

Actual: The effective PR diff has no `.github/workflows/` path. The workflow has no screen-test job or gate, and `gh pr checks 41` has no screen-test check. The PR description and phase roadmap state that PR-41 creates this job.

Consequence: The required visual contract is not enforced in CI, and the PR leaves the repository without the check that the roadmap assigns to it.

Correction: Add the screen-test workflow and stable gate, including the pinned Xvfb and Mesa setup, deterministic captures, decoded-pixel comparison, and the required tests and baseline.

Regression check: Run the new screen-test job twice and verify that the check exists, passes, and rejects a one-pixel baseline change.
